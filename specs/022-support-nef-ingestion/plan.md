# Implementation Plan: Ingest Nikon NEF Raw Format

**Branch**: `022-support-nef-ingestion` | **Date**: 2026-11-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/022-support-nef-ingestion/spec.md`

## Summary

Enable robust, full-fidelity ingestion of Nikon digital camera RAW files (`.NEF` / `.nef`) into the canonical media master archive. This requires:
1. Extending `exif_parser.rs` with a dedicated TIFF SubIFD dimension extractor so full raw sensor dimensions (e.g. 6000x4000) are extracted instead of the 160x120 thumbnail preview header.
2. Updating MongoDB incremental pre-filtering in `mongodb_sink.rs` so catalog entries that previously failed or lack cryptographic fingerprints are automatically re-extracted and self-healed rather than skipped.
3. Ensuring end-to-end ingestion routes NEF files to `<Year>/<DD-Mon-YYYY>/PhotosRaw/<filename>`, replicates to backup drives, and safely prunes source files.

## Technical Context

**Language/Version**: Rust 2021 edition  
**Primary Dependencies**: `tokio`, `nom-exif`, `kamadak-exif`, `blake3`, `mongodb`, `tracing`  
**Storage**: MongoDB (`media_assets` collection) + Local / External USB Hard Drives (APFS / exFAT)  
**Testing**: `cargo test` unit & integration test suites  
**Target Platform**: macOS (Apple Silicon M1 optimized) / Linux  
**Project Type**: CLI media ingestion & deduplication engine  
**Performance Goals**: Stream processing $\ge 30$ MB/s per drive over USB; sub-millisecond TIFF SubIFD header parsing  
**Constraints**: Zero unmonitored blocking I/O; no full-file memory buffering of large RAW files; strict archive write-protection on master directories  
**Scale/Scope**: Thousands of multi-megabyte (25MB - 50MB) camera RAW files across millions of cataloged media files  

## Constitution Check

- **Principle I (High-Throughput I/O & Hardware-Conscious Concurrency)**: PASS. SubIFD traversal reads only the initial header bytes without buffering multi-megabyte raw sensor payloads into memory.
- **Principle II (Domain-Driven Design & SOLID Boundaries)**: PASS. Changes are confined to the `ExifMetadataExtractor` infrastructure adapter and `MongoDbStorageSink` query filtering without polluting domain entities.
- **Principle III (Comprehensive Measurability & Observability)**: PASS. Extraction, hashing, and transfer operations maintain live progress indicators and elapsed time metrics.
- **Principle IV (Idiomatic Rust & Zero-Cost Reliability)**: PASS. Safe Rust code with exhaustive error handling and `thiserror` types. No `unwrap()` or `expect()`.
- **Principle V (Fault Isolation & Resilient Batch Ingestion)**: PASS. Corrupt files or parser errors are isolated into `ExtractionStatus::Failed` with diagnostic warnings, preventing batch termination.
- **Principle VI (Zero Hardcoded Credentials)**: PASS. All database configurations source credentials from environment variables.
